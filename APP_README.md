# app.py — README

## What This Is

The Gradio entry point for NCAIR-DSA. Runs the full pipeline live: audio capture → language detection → ASR → N-ATLaS structuring → keyword extraction → doctor review → database save → export. This is what your team runs in Colab to get a public demo link.

---

## Pipeline Order

```
Audio Capture
     │
     ▼
Audio-Based Language Detection  (nlp/audio_language_detect.py — runs BEFORE ASR)
     │
     ▼
Transcription  (asr/transcribe.py — per detected/confirmed language)
     │
     ▼
N-ATLaS Structuring  (nlp/structure_note.py)
     │         → Clinical Note (chief complaint, duration, severity, history)
     │         → Possible Recommendations (separate, hedged field)
     ▼
Keyword Extraction  (nlp/extract_keywords.py — runs on the ENGLISH note, not raw transcript)
     │
     ▼
Doctor Review (tabbed UI)
     │
     ▼
Save to Database  (templates/clinical_note.py)
     │
     ▼
Export (CSV / TXT)
```

## Role-Based Interface

The app now opens on a **landing page** — role selection is the first and only thing visible when the app starts. Nothing else renders until a role is chosen.

- **Nurse** — after clicking "Continue," sees only: Patient ID, Language, Audio capture, Language detection button/status, Transcribe button, raw transcript display. No access to clinical note editing, recommendations, save, history, or exports.
- **Doctor** — after clicking "Continue," sees everything: capture section plus the full tabbed review, save button, patient history lookup, and both export buttons.

A **"← Back to Role Selection"** button sits at the top of the main app view, letting anyone return to the landing page and pick a different role without restarting the whole app. Whatever was already entered in the form fields is not wiped when going back — it's just hidden again until a role is re-selected.

**Security note — read this before presenting:** role selection here is a **UI/workflow convenience, not access control**. There is no authentication behind it — anyone can click "Continue as Doctor" and immediately see the full clinical review, recommendations, and export tools. This is intentional and disclosed, not an oversight: building real authentication (login, credential checks tied to staff identity) was judged out of scope for a Colab-hosted prototype. When presenting, say this explicitly rather than letting the role screen imply more security than it has — "in a real deployment, this would be backed by actual staff login credentials" is the honest framing.

Implemented via two top-level `gr.Group()` containers (`landing_group`, `main_app_group`), toggled by `enter_app()` on the Continue button and `back_to_role_selection()` on the Back button. Doctor-only sections within `main_app_group` (review tabs, save, history, exports) are further gated by a second layer of `gr.update(visible=...)`, so a Nurse who clicks Continue still only sees the capture section, not the doctor tools.

## Tab Structure (Doctor View)

Ordered by prominence, per supervisor direction — clinical note must be the most prominent element:

1. **🩺 Clinical Note** (default, opens first) — Chief Complaint, Duration, Severity (with a color-coded badge: green/mild, amber/moderate, red/severe), Relevant History. All editable. Grounded strictly in what the patient said.
2. **💡 Possible Recommendations** (second tier) — AI-suggested considerations, editable. Always displayed with a hardcoded disclaimer prepended in code (see below) — never relies on the model to include hedging language itself.
3. **🔑 Keywords** (minor, de-emphasized) — read-only quick-reference terms, explicitly labeled "not part of the saved clinical note."

---

## The Disclaimer — Why It's Hardcoded, Not Model-Generated

```python
RECOMMENDATIONS_DISCLAIMER = (
    "⚠️ For doctor consideration only — NOT a diagnosis. "
    "This is a model-generated suggestion and may be incomplete or inaccurate. "
    "Clinical judgment should always take precedence.\n\n"
)
```

This string is prepended in Python code before the Possible Recommendations field is ever displayed. It is never generated by N-ATLaS. This matters because LLMs are inconsistent about following soft instructions like "always include a disclaimer" — a hardcoded string in the UI layer cannot be silently dropped from a given output the way a model-generated one could be.

On save, `handle_save_click()` strips this disclaimer back off before writing to the database, so it isn't duplicated every time the record is displayed again later.

## Language Detection Flow

1. Nurse records/uploads audio
2. Clicks "🌐 Detect Language from Audio" — calls `detect_audio_language()` from `nlp/audio_language_detect.py`, which runs Whisper's language-ID head directly on the audio (before any transcription happens)
3. If confident, the detected language auto-fills the dropdown and a confirmation message shows the confidence score
4. If not confident, the dropdown falls back to whatever was manually selected, with a warning message explaining why

**Known gap:** Igbo is not a confirmed standard Whisper language (Hausa and Yoruba are). This needs empirical testing in Colab before relying on it for a live demo — the confidence threshold and manual fallback exist specifically to protect against a silent misdetection.

## Exports

- **CSV** (`handle_export_csv`) — dumps the entire `clinical_visits` table via `templates/clinical_note.py`'s `export_all_records_to_csv()`. Available as a downloadable file through `gr.File`.
- **Plain Text** (`handle_export_transcript_txt`) — exports one patient's translated/structured note AND their original untranslated transcript in the same file, clearly separated with headers. This exists specifically so a mistranslation or ASR error doesn't destroy the original record — the source text is always recoverable.

## Google Drive — Mounting Requirement

**`drive.mount()` must be called from a live Colab notebook cell, never from inside `app.py`.** Running `!python app.py` executes it as a subprocess with no attached kernel, so any attempt to mount Drive from inside the script will fail with `'NoneType' object has no attribute 'kernel'`.

Correct sequence:

```python
# Cell 1 — run first, on its own
from google.colab import drive
drive.mount('/content/drive')
```

```python
# Cell 2 — after Drive is mounted
!python app.py
```

`templates/clinical_note.py` checks whether `/content/drive/MyDrive` exists and uses it automatically if so — no mounting logic needed inside `app.py` itself.

## Common Issues

| Symptom | Cause | Fix |
|---|---|---|
| `AttributeError: 'NoneType' object has no attribute 'kernel'` | `drive.mount()` called from inside `app.py` | Move the mount call to its own notebook cell, before running `app.py` |
| `sqlite3.DatabaseError: file is not a database` | Corrupted/empty `notes.db` left over from a prior failed run | `!rm -f data/notes.db` (or the Drive path) and re-run |
| `Error saving record: table clinical_visits has no column named X` | Old `notes.db` created before a schema change (e.g. before `possible_recommendations` was added) | **Now auto-fixed** — `init_db()` runs a migration check on every startup and adds any missing columns automatically. No manual deletion needed as of this version. See `templates/README.md` for details. |
| Keywords always show "None" | Keyword extraction was pointed at the raw (non-English) transcript instead of the structured English note | Already fixed — `extract_keywords()` runs on `english_note_text`, not `transcript`, in `process_patient_intake()` |
| Link shows `ERR_CONNECTION_REFUSED` | Opened the `127.0.0.1` local URL instead of the `https://xxxx.gradio.live` public one | Copy the `https://` link specifically |
| `ModuleNotFoundError: No module named 'templates.clinical_note'` | Filename mismatch (e.g. `clinical_notes.py` vs `clinical_note.py`) | Confirm exact filename matches the import statement |
